# Defensive Security Intro: TryHackMe Walkthrough

Room: https://tryhackme.com/room/defensivesecurityintro

Defensive security focuses on reducing the chance of compromise, detecting suspicious activity, and responding when something goes wrong. Offensive testing helps discover weaknesses; defensive work uses that knowledge to protect systems, investigate events, and improve controls.

## 1. Common defensive roles

- **Security Operations Centre (SOC) analyst:** monitors alerts, investigates suspicious events, and escalates incidents.
- **Incident responder:** contains and investigates confirmed or suspected incidents.
- **Threat hunter:** searches for suspicious activity that may not have triggered an existing alert.
- **Digital forensics analyst:** collects and analyses evidence to reconstruct events.
- **Detection engineer:** builds and maintains rules, queries, and alerting logic.
- **Security engineer:** implements and maintains protective controls.

Titles vary between organisations. A small team may combine several roles, while a large organisation may separate them.

## 2. Understand common tools

- **SIEM:** centralises and correlates logs from endpoints, servers, identity systems, and network devices.
- **EDR:** monitors endpoint behaviour and supports investigation and response.
- **Firewall:** controls traffic according to network policy.
- **IDS/IPS:** detects suspicious network activity and, in prevention mode, may block it.
- **Threat intelligence:** provides context about indicators, techniques, infrastructure, and adversaries.
- **Ticketing and case management:** records investigations, decisions, ownership, and follow-up work.

No single tool provides complete visibility. Logs may be missing, delayed, or incorrectly configured, so analysts must understand what the sensor can and cannot observe.

## 3. Alerts and indicators

An indicator of compromise (IOC) is an observable clue, such as a suspicious domain, file hash, IP address, or registry change. An alert is a signal generated by a rule or analytic. An alert is not automatically a confirmed incident; it needs investigation.

A useful triage process asks what triggered the alert, which asset and identity were involved, whether the behaviour is expected, and what related events occurred before and after it.

## 4. Basic investigation workflow

1. Read the alert details and preserve the original event.
2. Identify the affected user, host, time window, and detection rule.
3. Search for related authentication, process, network, and file events.
4. Compare the activity with expected behaviour and known maintenance.
5. Determine whether the evidence supports a benign event, suspicious activity, or a likely incident.
6. Contain or escalate according to the organisation's procedure.
7. Record evidence, reasoning, and next actions.

Do not close an alert solely because a hostname or IP looks familiar. Attackers can use legitimate infrastructure, and compromised accounts often produce events that resemble normal activity.

## 5. Prevention, detection, and response

Prevention includes patching, secure configuration, least privilege, multifactor authentication, backups, and network segmentation. Detection relies on useful logs, reliable time synchronisation, well-tested rules, and adequate coverage. Response includes containment, evidence preservation, eradication, recovery, and lessons learned.

These layers support each other. A prevention control can fail, and a detection rule can miss activity, so defence should not depend on one control alone.

## 6. Working through the room

For each question, identify whether it describes a defensive role, a tool, an indicator, or a stage in the response process. When the task gives a scenario, use the role's actual responsibility rather than guessing from the title. A SOC analyst usually triages and escalates; an incident responder coordinates containment and recovery; and a forensic analyst focuses on evidence and reconstruction.

## What I took from this room

Defensive security is a continuous cycle: reduce exposure, observe system behaviour, investigate meaningful signals, respond proportionately, and improve controls based on what was learned.
